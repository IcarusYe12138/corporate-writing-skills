# 好写作原则（Writing Principles）

> 任何文体的起草与审查都适用本文档。五条原则按"清晰 → 简洁 → 语气 → 自信 → 外观"排序，修订时按四层流程倒查。

## 核心理念：写作是传播设计

写作不是"写完再想给谁看"，而是先设计传播方案再落笔。衡量标准只有一个：读者是否**易读、易懂、易行动**。书面沟通能力长期位列雇主最看重的核心素质之一——企业写作质量直接等于职业可信度。（若引用具体调查比例，须标注调查方、年份与样本范围；无来源的百分比不写进稿件。）

## 原则一：清晰优先（Clarity First）

### 10 秒测试

读者扫视开头 10 秒内必须能回答三个问题：
1. 发生了什么 / 这是什么事？
2. 跟我有什么关系？
3. 我需要做什么？

任何一个问题答不出，重写开头。**关键信息前置**：把结论、请求、截止日期放在句首和段首，而不是"铺垫半天才说重点"。

### 窗玻璃理论（Windowpane Theory）

好文字像干净的窗玻璃——读者透过文字看到信息本身，意识不到文字的存在。当读者开始注意到"这个句子写得真绕"，窗玻璃就起了雾。自检方法：读一遍自己的句子，如果需要回读才能理解，就是雾。

### 具体做法

- 一句一个主要意思。从句套从句是窗玻璃上的雾。
- 用具体词代替抽象词："下周五前提交"优于"尽快提交"；"销售额下降 12%"优于"业绩承压"。
- 先说结论再说原因（倒金字塔），除非受众文化预期相反。
- 术语只在读者确实懂时使用（回到 O1：他们是谁）。

## 原则二：简洁（Conciseness）

简洁不是删信息，是删噪音。每个词都要回答"删掉它信息会损失吗？"——不会就删。

| 冗余表达 | 精简为 |
|---|---|
| 作出决定 | 决定 |
| 进行讨论 | 讨论 |
| 在……的情况下 | 若…… |
| 就……方面而言 | 关于…… / 直接删 |
| due to the fact that | because |
| in order to | to |
| at this point in time | now |
| 我们想要表达的是 | 直接说 |

其他规则：
- 名词化还原为动词（"provide assistance to" → "help"；"实施评估" → "评估"）。
- 能用主动语态不用被动（"财务部审批了预算"优于"预算被审批了"）——但需要淡化执行者时用被动（"文件已丢失"）。
- 删掉开头的空转句："I am writing to inform you that…" 直接删，说事本身。

## 原则三：语气匹配受众（Tone Fits Audience）

语气由 O1–O5 分析决定，不是个人风格偏好。默认基准是 **direct without being cold**（直接但不冷漠）——立场明确、语言简洁，但保留对读者的尊重与共情。

### 语气光谱（按读者关系与消息性质定位）

| 场景 | 语气定位 | 特征 |
|---|---|---|
| 对上级/董事会 | 正式、结论先行 | 完整句式、数据支撑、给选项而非抛问题 |
| 对客户 | 专业、以对方收益为轴 | "您将获得……"而非"我们提供……" |
| 坏消息（服务中断、裁员） | 冷静、共情、行动导向 | 先说影响与补救，再解释原因，不找借口 |
| 对内部同事 | 直接、平等 | 短句、要点化、明确谁在什么时间做什么 |
| 危机声明 | 坦诚、负责、克制 | 不回避坏词、不甩锅、不承诺做不到的事 |

### 坏消息的信息顺序

1. 说清事实与影响（读者最关心的）
2. 说明正在采取的行动
3. 给出读者可做的事
4. 最后才解释原因（如果必须）

不要用"我们很遗憾地通知您"拖 50 字才说正事。

## 原则四：自信表达（Confident Writing）

削弱词（hedges）让文本显得犹豫、不可信。企业写作中明确立场比"礼貌性含糊"更专业。

**削弱词删除清单**：

| 英文削弱词 | 中文削弱词 |
|---|---|
| just, only | 只是、仅仅是 |
| maybe, perhaps, possibly | 可能、或许、大概 |
| a little, somewhat, slightly | 一点、稍微、有点 |
| I think, I believe, in my opinion | 我觉得、我认为（非必要不加） |
| sort of, kind of, or something | 之类的、大概 |
| we hope to, we would like to | 我们希望（改为"我们将"） |

**改写对比**：

- ❌ I just think we maybe should perhaps reconsider the deadline a little.
- ✅ We should move the deadline to 30 November.
- ❌ 我们或许可以稍微考虑一下调整时间安排的可能性。
- ✅ 我们建议将截止日期调整至 11 月 30 日。

注意：共情场景（道歉、安抚）中适当的缓和不是削弱，是语气需要——"我们深知此次中断给您带来的不便"中的"深知"不能删。

## 原则五：可读性外观（Readable Appearance）

读者先看到版面，再读到文字。手机屏幕上：

- 段落不超过 3–4 行，超了就拆。
- 并列信息用列表，不要用逗号串成一句。
- 数字和日期突出显示（或放句首）。
- 一个屏幕放不下的段落就是太长的段落。
- 标题和小标题要能独立传递信息（读者只看标题也应该知道大意）。

## 四层修订流程

**顺序执行，不要混改**——先润色措辞再调结构，措辞会白润色。

1. **内容编辑 Content Editing**：信息完整吗？证据可靠吗？有无编造事实？该说的说了吗？不该说的删了吗？
2. **结构编辑 Structural Editing**：顺序符合读者预期吗？最重要的信息在最前吗？每段各司其职吗？（此层可能整段移动或删除）
3. **风格编辑 Style Editing**：语气匹配受众吗？有削弱词、冗词、名词化滥用吗？（此层才动词句）
4. **校对 Proofreading**：拼写、语法、标点、格式、名称与数字。（大声读出来是发现语病的最快方法）

每层改完再进入下一层。复杂文本每层之间隔开时间（至少一顿饭的间隔），新鲜感会让校对失效。
